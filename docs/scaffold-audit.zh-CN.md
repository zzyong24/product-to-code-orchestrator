# 脚手架结构与运行审计

## 3.30.0：结合项目现状的运行整改（2026-10-20）

本轮依据外部 Agent 的意见、脚手架当前实现和既有产品的只读抽查实施整改。外部意见将旧项目配置与新项目默认行为混在一起：当前初始化早已只挂两个核心 hook，但旧项目仍可能保留重型 Stop/PostToolUse；源码有 CI 模板，不代表产品实际接入，也不代表远端已设 required check。版本号一致不能证明迁移完成。

没有采用“领先业界几档”、通用 WIP 数量或 PR 行数作为工程依据。`🔨 待办` 是状态语义冲突，不能直接当作真实在制任务；磁盘证据体积不能等同于 Git 或上下文体积。原报告关于归档重复、远端分支存在性和行业指标的判断也不能代替当次核实。

| 已证实的问题 | 本轮处理及边界 |
| --- | --- |
| 规则随本机 skill 变化，脱离原机器可能断链 | 项目固定带逐文件哈希和版本锚的规则包，规划器优先读取；损坏时拒绝回退，项目修改保留并提供独立更新候选 |
| 日常收口执行任意项目命令，既慢又可能产生副作用 | quick/read-only 保留机械检查，跳过项目 lessons、资产示例和跨项目实时验证；清楚报告覆盖缺口 |
| 完整 lesson 检查无预算、无逐项进展 | 串行执行器按项目预算运行，报告开始、耗时及失败尾部；超时、取消、未结清子进程都不能通过。进程清理不冒充安全沙箱 |
| 本地门被绕过后没有可靠 CI 接入入口 | 显式 `--ci github`，模板含快速治理检查和独立产品验证；已有 workflow 生成候选，远端 required check 仍须实际核实 |
| 更新了运行时，旧宿主配置、引用与 CI 缺口仍不透明 | 只读 doctor 区分确定错误、迁移警告和静态未知；不执行项目配置中的命令 |
| 子检查 exit 0 的警告被摘要说成 clean | 文档、知识层和看板告警保留到 reconcile 输出；RUNAWAY 硬阻断维持 |
| 提交后的工作区干净，使迭代文件数变成零 | v2 迭代记录使用提交差异与本轮工作区变化并集，历史 v1 不重写 |
| 会话 hook 注入旧的强制并行、禁止多步骤与无条件审核 | 注入与当前 buildout/maintenance、依赖就绪顺序及按需任务包一致 |
| 部分初始化、重复更新与路径别名存在恢复缺陷 | 不完整初始化明确失败并给出受保护的迁移入口；旧备份不覆盖；修复带空格和 shell 特殊字符路径，以及软链接 CLI 静默退出 |

独立前向验证使用带空格的陌生临时目录，实际执行初始化、搬迁、断开本机 skill 路径、PLAN/BUILD 读取、CI 接入和更新。验证者还用本地无害标记命令核对 quick/full 的副作用边界，故意制造失败验证非零结果；检查过程中发现的部分初始化、历史备份覆盖和 `/tmp` 路径别名问题均修复并通过现场复验。故意保留的半初始化目录仍需审核迁移候选，明确报错就是该场景的预期行为。

最终 `tools/selfcheck.sh` 通过：349 项测试、0 失败、0 跳过；运行器失败处理语义、植入断链检测和全新模板协调检查通过。技能格式校验与 `git diff --check` 通过。安装器最后对自定义 hook wrapper 的保护另做定向回归；复验保留复合命令原文，只刷新安装器生成的简单调用。技术自检与独立实际试用分别完成，未据此声称实际产品已经构建或通过验收。

CreatorOS 仅做只读诊断，未升级、压缩看板、删除证据或修改其 CI。既有产品的 RUNAWAY、旧 hook、引用与 workflow 配置需要结合产品正在进行的工作单独迁移。此次没有新增 DORA 指标账本：周期、部署失败与返工率需要真实任务/部署事件，不能从 emoji 或修复类任务名称估算。也没有测量全项目检查加速比例，quick 的覆盖范围与 full 不同。

下面保留 3.29.0 的文档整改记录，验证数量与结论属于当时版本。

## 3.29.0：文档结构整改

本轮检查以 3.29.0 为准，目标是减少互相争夺决定权的规则，让 Agent 用最少必要材料完成真实任务。检查依据包括本仓库的初始化器、上下文规划器、状态与验收脚本，以及本地 `Workbase/hypit/skills/hypit/SKILL.md` 和其项目文件、评审参考。没有把 Hypit 的视频业务流程搬进开发流程。

## 从什么原则出发

每份 Agent 文档只需要回答四件事：何时读、解决什么决定、事实由谁维护、凭什么继续。常驻入口给目标和导航；细节在当前任务需要时读取；程序已经能检查的事实由程序检查；历史事故不变成每次开工都必须背诵的规则。

借鉴 Hypit 的是目标驱动、明确项目边界、按职责组织资料和在需要处链接参考。它允许执行者运用判断，同时要求诚实说明结果与缺口；这比增加命令式清单更适合本脚手架。

## 本轮解决的冲突

| 原问题 | 现在的处理 |
| --- | --- |
| 授权散落在入口、路由、状态机与各门中，阶段切换反复确认 | 公共流程维护授权原则，其他文件说明本阶段条件；沿用已有授权 |
| 确认产品范围被写成自动授权无人值守 | 范围与执行授权分开，自治仍需结构化配置和预检 |
| BUILD 可有多个步骤，看板却禁止多步骤并要求一次做完 | 中间步骤保存提交，任务保持进行中；最终步骤才结束任务 |
| 只读评审又被要求写 RUN_EVENTS | 评审只输出结论，运行器负责状态与事件写入 |
| 文档称评审者可设置 e2e_verified | 明确运行器的写入路径，双重通过也不自动授权发布 |
| 写死每十任务自动审计、完整看板注入及默认全部钩子 | 按真实代码说明节拍、队头注入和初始化挂载内容 |
| 每个界面必须有第二语言 | 按产品需要启用语言；中文产品可只支持中文 |
| 任意项目套固定表/接口额度、累计天数和豁免次数 | 删除无校准额度，保留实际范围、复杂度、威胁与哈希绑定授权 |
| 纯前端也可能被要求创建后端、数据库或适配器 | 架构和契约只记录实际职责；无对应需求不增层 |
| 所有测试夹具都必须退役 | 临时演示依赖退出，独立回归夹具保留 |
| 服务契约在实现前要求给出尚不存在的运行消费行号 | 契约阶段给责任与验收，实现后核对真实消费者 |
| 本地完整提示日志被认为不存在隐私问题 | 统一按观测规则最小记录、排除敏感内容 |
| 登记表声称外部技能已安装、限定供应商和历史型号 | 改为方法指针，工具与模型以当前宿主为准 |
| 模板重复字段清单和逐节说明，空表被当作完整性义务 | 一次说明用途与实际字段，不适用章节直接省略 |
| 中文入口仍按英文空格统计长度，测试锁定英文口号 | 改用 UTF-8 字节预算，保留路径、协议与行为回归 |

资产库附带说明也改为中文，并移除了无证据的通用数量阈值。熔断接入示例原先预领取所有候选许可，却可能提前返回导致未使用许可泄漏；说明改为实际尝试前领取、逐次结清，不再提供误导性整段骨架。

## 文件怎样被读到

“没有静态引用”不等于死文件。初始化模板、运行器提示和人工参考的入口不同，不能仅靠全文搜索一刀删除。

| 层次 | 入口与消费方式 | 维护边界 |
| --- | --- | --- |
| `SKILL.md`、`agents/openai.yaml` | 宿主技能发现与触发 | 简短目标、适用范围、下一步导航 |
| `AGENTS_TEMPLATE.md` | 初始化生成项目 AGENTS.md | 项目执行入口；不重复整套规则 |
| `workflows/_COMMON.md`、`rules/global-rules.md`、`gates/_GATE_EVIDENCE.md` | 规划器的公共读取集合 | 授权、最小实现、公共证据各自唯一维护 |
| `workflows/v3-*.md` 与阶段门、主要模板 | `context-plan.mjs` 的阶段集合 | 当前阶段目标、产物与推进条件 |
| 界面、架构、知识层、研究、自治、跨项目规则 | 规划器根据当前任务与配置激活 | 不因未激活而创建空材料 |
| `prompts/project-bootstrap.md` | 路由在首次实现时指向 | 可运行基线，不反复初始化 |
| `prompts/agent-architecture-initialization.md` | Agent 产品的 CONTRACT 与首次骨架引用 | 内核与工具边界，不作用于普通业务任务 |
| `prompts/spec-reviewer.md`、`spec-cross-audit.md` | 稳定面正式评审、多模块一致性需要时 | 只核对已确认范围，不成为第二个产品作者 |
| `prompts/product-audit.md`、`prelaunch-engineering-audit.md` | 整体联调或相应审计任务 | 产品连续性与工程上线条件分工 |
| `prompts/subagent-dispatch.md`、`harness/PARALLEL.md` | 已授权且适合委派时 | 有边界的子任务，主会话唯一集成 |
| `harness/coding-agent.md`、两份评审提示 | `harness/run.sh` 直接读取 | 串行 Claude CLI 适配，不冒称 Astra 启动器 |
| `templates/knowledge/*` | `init-module.sh` 动态拼接模板名，部分模板按知识任务选用 | 动态入口保留，不按“未发现字面引用”删除 |
| 决策、清单、词汇、看板、架构模板 | `init-project.sh` 按规模复制 | 机器字段不翻译，项目内容写中文 |
| 追踪、范围、默认假设、测试、模拟、联调、指标等模板 | 对应任务按需使用，详见下表 | 可合并到现有产物，不额外要求独立文件 |
| `decisions/` 模式和资产卡 | 有实际选型或复用需要时检索 | 参考资料，不常驻；候选不等于已生产验证 |
| `docs/`、README、CHANGELOG | 用户教程与维护追溯 | 不作为运行规则重复注入 |

`gates/12-service-contract-gate.md` 仅保留旧路径转发，规划器与 CONTRACT 已直接使用 15b，不再把转发和正文都加载。三个历史通用提示路径也只转向公共流程，避免旧引用失效。

删除无独立消费入口且职责已重复的 `rules/code-retrieval-rules.md` 和 `rules/external-skill-safety-rules.md`：检索归公共实现规则；外部来源与能力边界归 `prompts/external-skill-dispatch.md`。没有为保住文件而把它们强行加进常驻读取。

## 按需模板的使用边界

| 模板 | 什么时候需要 |
| --- | --- |
| IA_SPEC / BUSINESS_FLOW / LIGHT_DOMAIN_MODEL | L 类复杂度确实需要从产品总纲拆开时 |
| MODULE_WORKFLOW_SPEC / BACKEND_SPEC | 后端模块有独立职责、现有契约不足以说明时 |
| COMPONENTS_SPEC | 实际复用组件或复杂状态需要独立契约时 |
| UI_MOCK_PROMPT / HOUSE_STYLE | 视觉探索或交接时；HOUSE_STYLE 不自带风格 |
| MOCK_DATA_SPEC | 有临时开发演示数据需要接真退出时 |
| TEST_PLAN | 验证复杂度需要单独说明时 |
| FRONTEND_VALIDATION_REPORT | 实际界面旅程验收；机读证据不可删 |
| ID_REGISTRY / TRACEABILITY_MATRIX | 项目追踪检查已启用时 |
| CHANGE_IMPACT / DEFAULT_ASSUMPTIONS | 实质变更或多项假设需要单独追踪时 |
| SCOPE_LEDGER | 同一能力跨任务增长需要人读汇总时 |
| LESSON_LEDGER / METRICS | 实际启用教训沉淀或已有指标文件时；不能冒充默认初始化产物 |
| INTEGRATION_REPORT / RELEASE_REVIEW | 汇总联调与发布，简单项目允许合并 |
| 结构化 JSON 授权、研究、跨项目模板 | 由对应程序协议和事实触发；保留字段与格式 |

## 语言与兼容性

Agent 说明和新填写内容使用中文。文件路径、CLI 参数、JSON/YAML 键、机器表头、状态枚举、ID 和代码示例的标识符保留原样，例如 `compact`、`EVAL_VERDICT`、`platform_execution_matrix`。把这些也翻译会破坏现有项目和解析器。

历史 CHANGELOG、已有研究引文、版权与许可证内容不重写成新的事实。本轮未批量改写已初始化的产品目录；产品更新应走受支持的 `--update`，保护项目定制和运行记录。

## 验证方式

本轮已通过技能格式校验和完整 `tools/selfcheck.sh`：294 项测试通过、0 失败，运行器失败处理语义、故意植入的追踪断链检测、全新模板初始化与协调检查均通过。`git diff --check` 无格式错误。

上下文回归核对实际返回路径和条件加载，状态/授权/收据回归继续验证程序行为；没有为了文字变短删除必要失败测试。跨项目测试夹具改为按稳定 YAML 字段定位，避免翻译注释影响测试构造；自检显式使用 TAP 输出测试结果。

本轮没有进行 GPT-6 Astra 的性能 A/B 测量。可以确认的是入口与模板更短、重复加载更少、规则边界更一致；不能据此宣称具体速度或成功率提升。
